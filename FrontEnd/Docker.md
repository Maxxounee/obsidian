## Getting Stared

```terminal
docker run -d -p 80:80 docker/getting-started
```

* `-d` - Запустить контейнер в detached mode (в фоновом режиме)
* `-p 80:80` — map port 80 of the host to port 80 in the container
* `docker/getting-started` — the image to use

Флаги из одного символа можно комбинировать:

`docker run -dp 80:80 docker/getting-started`

## The Docker Dashboard

В Docker Desktop можно посмотреть запущенные контейнеры.

### Что такое контейнер (container)?

Контейнер — еще один процесс на компьютере, который изолирован от других процессов на хосте. 


### Что такое container image (образ контейнера)?

Когда контейнер запущен, он использует изолированную файловую систему. Эта пользовательская файловая система обеспечивается образом (image) контейнера. Поскольку образ содержит файловую систему контейнера, он должен включать в себя все необходимое для запуска приложения: зависимости, настройки, скрипты и так далее. Образ так же содержит другие настройки для контейнера, такие как переменные окружения, стандартные команды для запуска и другие данные.


## Our Application

### Создание образа контейнера приложения

Чтобы создать приложение, мы должны использовать Dockerfile. Dockerfile это простой text-based script инструкций, который используется для создания образа.

1. Создайте файл с названием Dockerfile в той же директории, что и `package.json` со следующим содержимым:

```Dockerfile
FROM node:18-alpine
WORKDIR /app
COPY . .
RUN yarn install --production
CMD ["node", "src/index.js"]
```

2. В терминале пройдите до директории с Dockerfile и создайте образ, используя команду `docker build`

```terminal
docker build -t getting-started .
```

Это команда использует Dockerfile для создания нового образа. Вы могли заметить, что было скачано множество "слоев". Это произошло, потому что мы проинструктировали builder о том, что нам нужно начать с образа `node:18-alpine`. Но поскольку у нас не было его на хосте, образ необходимо было скачать.

После того, как образ был скачан, мы скопировали его в наше приложение и использовали `yarn`, чтобы установить зависимости нашего приложения. Директива `CMD` определяет стандартную команду для запуска, когда мы запускаем контейнер из этого образа.

Наконец, флаг `-t` помечает наш образ. Это человекочитаемое название конечного образа. Поскольку мы назвали образ `getting-started`, мы можем обращаться к этому образу, когда запускаем контейнер.

Точка (`.`) в конце команды говорит, что Docker должен искать Dockerfile в текущей директории.

### Запуск контейнера приложения

Теперь, когда у нас есть образ, давайте запустим приложение! Чтобы это сделать, мы будем использовать команду `docker run`:

1. Запустите ваш контейнер, используя команду `docker run` и укажите имя образа, который мы только что создали:

```terminal
docker run -dp 3000:3000 getting-started
```

Мы запустили контейнер в фоновом режиме (detached mode) (флаги `-d` и `-p`) и создали mapping между портом хоста и портом контейнера. Без мапинга портов у нас не будет доступа к приложению

2. Через несколько секунд, откройте в вашем браузере `http://localhost:3000` и вы увидите наше приложение.

На данном этапе у нас есть запущенное todo list приложение с несколькими пунктами. Теперь давайте сделаем несколько изменений и узнаем об управлении нашими контейнерами.

Если мы взглянем на Docker Dashboard (Docker Desktop), мы увидим два запущенных контейнера (туториал и todo приложение).

## Updating our App

Как маленькое изменение, нас попросили изменить "empty text", когда у нас нет пунктов в todo list

### Обновление нашего кода

1. В `src/static/js/app.js` поменяйте строку 56:

```html
<p className="text-center">You have no todo items yet! Add one above!</p>
```

2. Давайте соберем нашу обновленную версию образа, используя ту же команду, что мы использовали ранее:

```terminal
docker build -t getting-started .
```

3. Запустим новый контейнер, используя обновленный код:

```terminal
docker run -dp 3000:3000 getting-started
```

Мы получаем ошибку:

```
docker: Error response from daemon: driver failed programming external connectivity on endpoint laughing_burnell (bb242b2ca4d67eba76e79474fb36bb5125708ebdabd7f45c8eaf16caaabde9dd): Bind for 0.0.0.0:3000 failed: port is already allocated.
```

Что случилось? Мы не можем запустить новый контейнер, потому что наш старый контейнер все еще запущен. Причиной этой проблемы является то, что контейнер использует порт хоста 3000 и только один процесс на машине может обращаться к определенному порту. Чтобы это исправить, мы должны удалить старый контейнер.

### Replacing our Old Container

Чтобы удалить контейнер, сначала он должен быть остановлен. После того, как он остановлен, он может быть удален. У нас есть два пути того, как мы можем удалить старый контейнер. Вы можете самостоятельно выбрать самый комфортный вариант.

#### Удаление контейнера, используя CLI

1. Получите ID контейнера, используя команду `docker ps`

```terminal 
docker ps
```

2. Используйте команду `docker stop` для остановки контейнера

```terminal
docker stop <the-container-id>
```

3. После остановки контейнера, вы можете удалить его, используя команду `docker rm`

```terminal
docker rm <the-container-id>
```

4. Вы можете остановить и удалить контейнер одной командой, добавив force флаг  

```terminal
docker rm -f <the-container-id>
```


#### Удаление контейнера, используя Docker Dashboard

1. В Docker Dashboard удалите контейнер из списка запущенных

Теперь мы снова можем запустить контейнер на порте 3000.


## Sharing our App

Мы создали образ, теперь поделимся им. Чтобы поделиться образом, нужно использовать реестр Docker (Docker registry). Стандартный реестр — это Docker Hub, откуда пришли все образы, которые мы использовали.

### Создание репозитория

Чтобы запушить образ, сначала нужно создать репозиторий в Docker Hub:

1. Перейдите в [Docker Hub](https://hub.docker.com) 
2. Нажмите _Create Repository_
3. Назовите репозиторий (getting-started). Убедитесь, что видимость установлена в _public_
4. Нажмите _Create_

Справа появится пункт _Docker commands_. Там указан пример команды, которую нужно запустить, чтобы запушить репозиторий.

### Pushing our image

1. В командной строке попробуйте использовать push command, которую мы видели в Docker Hub. 

```command
$ docker push docker/getting-started The push refers to repository [docker.io/docker/getting-started] An image does not exist locally with the tag: docker/getting-started
```

Получили ошибку. Push command искала образ, который назван `docker/getting-started`, но не нашла. Если запустить `docker image ls` мы не увидим образ.

Чтобы это исправить, нам нужно пометить (tag) существующий образ, который мы собрали.

2. Войдите в _Docker Hub_ кликнув sign in в Docker Desktop или используя команду `docker login -u YOUR-USER-NAME`
3. Используйте команду `docker tag`, чтобы дать образу getting-started новое имя. Удостоверьтесь, что изменили `YOUR-USER-NAME` на ваш Docker ID

```
docker tag getting-started YOUR-USER-NAME/getting-started
```

4. Теперь попробуйте запушить снова.

```
docker push YOUR-USER-NAME/getting-started
```
