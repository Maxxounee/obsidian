Это порождающий паттерн проектирования, который решает проблему создания различных продуктов, без указания конкретных классов продуктов.

Фабричный метод задаёт метод, который следует использовать вместо вызова оператора `new` для создания объектов-продуктов. Подклассы могут переопределить этот метод, чтобы изменять тип создаваемых продуктов.

**Применимость:** Паттерн можно часто встретить в любом PHP-коде, где требуется гибкость при создании продуктов.

**Признаки применения паттерна:** Фабричный метод можно определить по создающим методам, которые возвращают объекты продуктов через абстрактные типы или интерфейсы. Это позволяет переопределять типы создаваемых продуктов в подклассах.

```php
namespace RefactoringGuru\FactoryMethod\Conceptual;
/**
 * Класс Создатель объявляет фабричный метод, который должен возвращать объект
 * класса Продукт. Подклассы Создателя обычно предоставляют реализацию этого
 * метода.
 */
abstract class Creator {
	/**
	 * Обратите внимание, что Создатель может также обеспечить реализацию
	 * фабричного метода по умолчанию.
	 */
	abstract public function factoryMethod(): Product;

	/**
	 * Также заметьте, что, несмотря на название, основная обязанность 
	 * Создателя не заключается в создании продуктов. Обычно он 
	 * содержит некоторую базовую
	 * бизнес-логику, которая основана на объектах Продуктов, возвращаемых
	 * фабричным методом. Подклассы могут косвенно изменять эту бизнес-логику,
	 * переопределяя фабричный метод и возвращая из него другой тип продукта.
	 */
	public function someOperation(): string {
		// Вызываем фабричный метод, чтобы получить объект-продукт.
		$product = $this->factoryMethod();
		
		// Далее, работаем с этим продуктом.
		$result = 
			"Creator: The same creator's code has just worked with " 
			. $product->operation();
			
		return $result;
	}
}

/**
 * Конкретные Создатели переопределяют фабричный метод для того, чтобы 
 * изменить
 * тип результирующего продукта.
 */
class ConcreteCreator1 extends Creator {
	/**
	 * Обратите внимание, что сигнатура метода по-прежнему использует тип
	 * абстрактного продукта, хотя фактически из метода возвращается 
	 * конкретный продукт. Таким образом, 
	 * Создатель может оставаться независимым от
	 * конкретных классов продуктов.
	 */
	public function factoryMethod(): Product {
		return new ConcreteProduct1();
	}
}

class ConcreteCreator2 extends Creator {
	public function factoryMethod(): Product {
		return new ConcreteProduct2();
	}
}

/**
 * Интерфейс Продукта объявляет операции, которые должны выполнять все
 * конкретные продукты.
 */
interface Product {
	public function operation(): string;
}

/**
 * Конкретные Продукты предоставляют различные реализации интерфейса 
 * Продукта.
 */
class ConcreteProduct1 implements Product {
	public function operation(): string {
		return "{Result of the ConcreteProduct1}";
	}
}

class ConcreteProduct2 implements Product {
	public function operation(): string {
		return "{Result of the ConcreteProduct2}";
	}
}

/**
 * Клиентский код работает с экземпляром конкретного создателя, хотя и 
 * через его базовый интерфейс. Пока клиент продолжает работать
 * с создателем через базовый
 * интерфейс, вы можете передать ему любой подкласс создателя.
 */
function clientCode(Creator $creator) {
	// ...
	echo "Client: I'm not aware of the creator's class, but it still works.\n"
		. $creator->someOperation();
	// ...
}

/**
 * Приложение выбирает тип создателя в зависимости от 
 * конфигурации или среды.
 */
echo "App: Launched with the ConcreteCreator1.\n";
clientCode(new ConcreteCreator1());
echo "\n\n";
echo "App: Launched with the ConcreteCreator2.\n";
clientCode(new ConcreteCreator2());
```

Давайте рассмотрим пример из жизни, но более простой (без бизнес логики в абстрактном классе Creator). У нас есть абстрактный класс Creator, который создаёт сообщения. Сообщения бывают 2-х видов: об успешном выполнении действия и об ошибке.

```php
abstract class Creator {
	public abstract function addMessage(string $text);
}

class SuccessCreator extends Creator {
	public function addMessage(string $text) {
		return [
			'status' => 'success',
			'text' => $text,
			'color' => 'green',
		]
	}
}

class ErrorCreator extends Creator {
	public function addMessage(string $text) {
		return [
			'status' => 'error',
			'text' => $text,
			'color' => 'red',
		];
	}
}

// client code
public function sendMessage(Creator $creator, string $text) {
	$message = $creator->addMessage($text);
	
	echo 'status: ' . $message['status'] . PHP_EOL;
	echo 'message: ' . $message['text'] . PHP_EOL;
	echo 'color: ' . $message['color'] . PHP_EOL;
}

try {
	$db->save(); // какая-то функция
	$this->sendMessage(new SuccessCreator(), 'OK');
} catch (Exception $e) {
	$this->sendMessage(new ErrorCreator(), $e->getMessage());
}
```

Рассмотрим ещё один пример.

Простейший пример паттерна "Фабричный метод" на PHP может быть реализован, например, для создания различных видов транспортных средств. Ниже приведен пример:

```php
// Абстрактный класс транспортного средства
abstract class Transport {
	abstract public function drive();
}

// Конкретные классы транспортных средств
class Car extends Transport {
	public function drive() {
		return "Driving a car.";
	}
}

class Bicycle extends Transport {
	public function drive() {
		return "Riding a bicycle.";
	}
}

// Фабричный метод для создания транспортного средства
abstract class TransportFactory {
	abstract public function createTransport();
}

// Фабричный метод для создания автомобиля
class CarFactory extends TransportFactory {
	public function createTransport() {
		return new Car();
	}
}

// Фабричный метод для создания велосипеда
class BicycleFactory extends TransportFactory {
	public function createTransport() {
		return new Bicycle();
	}
}

// Использование фабричного метода
$carFactory = new CarFactory();
$car = $carFactory->createTransport();
echo $car->drive() . "\n";

$bicycleFactory = new BicycleFactory();
$bicycle = $bicycleFactory->createTransport();
echo $bicycle->drive() . "\n";

```

В данном примере паттерн "Фабричный метод" позволяет делегировать создание объектов конкретным классам-фабрикам, что позволяет гибко управлять процессом создания объектов определенного типа.
