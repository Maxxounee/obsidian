
<blockquote>Объектно-ориентированное программирование, ООП – это одна из моделей (парадигм) разработки, подразумевающая организацию программного кода, ориентируясь на данные и объекты, а не на функции и логические структуры.</blockquote>

Идеологически, ООП — подход к программированию как к моделированию информационных объектов, решающий на более высоком абстрактном уровне основную задачу структурного программирования — структурирование информации с точки зрения управляемости. Это позволяет управлять самим процессом моделирования и реализовывать крупные программные проекты.

Управляемость для иерархических систем предполагает минимизацию избыточности данных (аналогичную нормализации) и их целостность, поэтому созданное удобно управляемым — будет и удобно пониматься. Таким образом, через тактическую задачу управляемости решается стратегическая задача — транслировать понимание задачи программистом в наиболее удобную для дальнейшего использования форму.

То есть фактически речь идёт о прогрессирующей организации информации согласно первичным семантическим критериям: «важное/неважное», «ключевое/подробности», «родительское/дочернее», «единое/множественное». Прогрессирование, в частности, на последнем этапе даёт возможность перехода на следующий уровень детализации, что замыкает общий процесс.

Обычный человеческий язык в целом отражает идеологию ООП, начиная с инкапсуляции представления о предмете в виде его имени и заканчивая полиморфизмом использования слова в переносном смысле, что в итоге развивает выражение представления через имя предмета до полноценного понятия-класса.

### Классы и объекты

Давайте представим какой-то объект из реального мира, например, дерево, которое растёт у нас во дворе. Давайте взглянем на него. Можем ли мы описать его полностью? Нет. Мы можем описать сотни внешних характеристик от цвета листьев в каждый месяц года до ширины трещин в коре, тысячи внутренних признаков, от структуры древесины до органических молекул. Но мы никогда не сможем описать дерево полностью, даже имея мощные микроскопы и самые передовые лаборатории.

Но мы можем выделить те качества, которые нужны для определённых задач, ситуаций. Например, столяра интересуют технические качества древесины, садовода - чем поливать, подкармливать, периоды цветения, плодоношения и т.п. Ландшафтного дизайнера интересует внешний вид и тень, которая будет от дерева в разное время суток. Пчеловода интересует период цветения, медопродуктивность (сколько килограмм мёда можно получить с 1 гектара сплошных посадок деревьев), пыльцепродуктивность и т.д.

Если говорить, например, о собаках, то владельца, кинолога, ветеринара, заводчика пограничника интересуют разные качества. То же самое и о людях, например, о работниках: на некоторых работах важен пол и возраст, а на некоторых - не имеет значения.

Смысл ООП заключается в том, что мы должны выделить интересующие нас общие свойства для какой-то сущности, а не интересующие нас свойства не учитывать.

Каждое определение класса начинается с ключевого слова `class`, затем идёт имя класса, а потом пара фигурных скобок, в которых определяют свойства и методы класса.

Для имени класса разрешается выбирать любое слово, при условии, что слово не входит в список зарезервированных слов PHP, начинается с буквы или символа подчёркивания и за которым следует любое количество букв, цифр или символов подчёркивания. Если задать эти правила в виде регулярного выражения, то получится следующее выражение: `^[a-zA-Z_\x80-\xff][a-zA-Z0-9_\x80-\xff]*$`.

Классы содержат константы и переменные, которые в классах называют свойствами; и функции, которые в классах называют **методами**. Свойства определяют интересующие нас характеристики. Методы определяют, что сущность умеет делать (интересного для нас).

```php
<?php  
class SimpleClass  
{  
// Объявление свойства  
public $var = 'значение по умолчанию'; // о слове public поговорим потом  
// Объявление метода  
public function displayVar() {  
echo $this->var;  
}  
}  
?>
```


### Объект 

**Объект** - это экземпляр класса. Он создаётся директивой `new`. Новый объект будет создан, если только конструктор не выдаст ошибку. Класс рекомендуют определять перед тем, как создавать экземпляр класса; иногда это обязательное требование.

Вернёмся к нашим примерам. Если класс - это дерево, то объект - это конкретное дерево, которое растёт у нас под окном. Если класс - это кошка, то объект - это конкретная кошка, которая живёт у нас дома, у которой есть конкретное имя, возраст и другие интересующие нас свойства. Методы, это то, что кошка умеет делать. Например, мяукать.

Доступ к свойствам и методам объекта осуществляется с помощью ->:

```php
<?php
class Cat   {   
	public $name;
	public $age;
	public $color;
	  
	public function say() {      
		echo 'miau';   
	}
}

$murka = new Cat();
$murka->name = 'Murka';
$murka->age = 3;
$murka->color = 'grey';

echo $murka->name . '  say:';

$murka->say();

?>
```

Результат:

Murka say: miau

Свойства могут задаваться в конструкторе при создании объекта (внутри круглых скобок после имени класса). Но для этого нужно соответствующим образом определить конструктор.

### Конструктор 

**Конструктор** - это специальный метод, который создаёт объект. `$murka = new Cat()` - объект мурка создаётся конструктором по умолчанию. Если мы хотим задать свойства при создании объекта, мы должны определить конструктор с параметрами в классе:

```php
<?php  
class Cat   {  
	public $name;
	public $age;
	public $color;

	public function __construct($name, $age, $color = 'grey') {
		$this->name = $name;      
		$this->age = $age;
		$this->color = $color;   
	}  
	
	public function say() {     
		echo 'miau'; 
	}  
}

$murka = new Cat('Murka', 3, 'grey');

echo $murka->name . '  say:';

$murka->say();

?>
```

Деструкторы рассматривать не будем, т.к. они очень редко используются (в php есть сборщик мусора, который автоматически удаляет объекты, на которые нет ссылок, высвобождая память).

### Клас как тип данных. Стандартные классы php. Библиотеки и фреймворки

С точки зрения программирования класс - это отдельный тип данных. То есть, мы по-возможности пользуемся стандартными типами данных, но, если их становится мало, создаём новый составной тип данных. А переменная созданного типа данных - это уже объект.

Стандартные типы данных - это тоже классы, написанные и протестированные ранее другими программистами и встроенные в php.

Создание нескольких классов в одном файле используется только при обучении. В реальных проектах для каждого класса создаётся отдельный файл, классы раскладываются по папкам в соответствии с принятой в проекте архитектурой приложения. Для подключения одного класса к другому над названием класса пишется команда 
`require '../relative/path/to/library/file.php'`
или 
`use '../relative/path/to/library/file.php'`
(В большинстве случаев рекомендуется использовать `require` для включения важных файлов, а `use` — для импорта классов или пространств имён, чтобы избежать повторения кода).

Бывают также и **библиотечные** классы. Это классы, написанные и протестированные ранее другими программистами. Эти классы не встроены в язык, но можно подгрузить библиотеку/класс в свою программу и использовать эти классы. Всегда лучше использовать уже отлаженное и протестированное, чем изобретать велосипед и писать самостоятельно классы, аналоги которых уже давно и успешно используются.

Для подключения сторонней библиотеки в PHP выполните следующие шаги:

1. Зайдите на сайт с библиотекой.
2. Скачайте архив и распакуйте его в папку с PHP-сценариями.
3. Подключите сценарии с классами библиотеки, например, указав над названием класса относительный путь к файлу (для подключения библиотечных классов и классов фреймворка используются те же require и use).
4. В коде создайте новые объекты этих классов и вызовите их методы.

Обратите внимание на наличие качественной документации, частоту использования другими программистами и набор предлагаемых возможностей.

**Фрефмворк** -  (англицизм, неологизм от framework «остов "Несущая конструкция"), каркас, рама; структура») — программная платформа, определяющая структуру программной системы; программное обеспечение), облегчающее разработку и объединение разных компонентов большого программного проекта. _Фреймворк_ отличается от понятия библиотеки тем, что последняя может быть использована в программном продукте просто как набор подпрограмм похожей функциональности, не влияя на архитектуру программного продукта и не накладывая на неё никаких ограничений. В то время как фреймворк диктует правила построения архитектуры приложения, задавая на начальном этапе разработки поведение по умолчанию — «каркас», который нужно будет расширять и изменять согласно указанным требованиям. 

Также, в отличие от библиотеки, которая объединяет в себе набор близкой функциональности, — «фреймворк» может содержать в себе большое число разных по тематике библиотек. Ключевым отличием «фреймворка» от библиотеки является инверсия управления "Инверсия управления"): пользовательский код вызывает функции библиотеки (или классы) и получает управление после вызова. Во «фреймворке» пользовательский код может реализовывать конкретное поведение, встраиваемое в более общий — «абстрактный» код фреймворка. При этом «фреймворк» вызывает функции (классы) пользовательского кода.

Самые популярные фреймворки php: laravel, yii, symphony. Хотя бы один нужно хорошенько изучить по видеоурокам из интернета, остальные нужно изучить хотя бы поверхностно. На чистом php большие проекты не пишут, любая it-компания при разработке ПО использует один или несколько фреймворков.
