Laravel сам умеет определять связные ключи (FK, RK) в таблицах и связывать их (`return $this->belongsToMany(Tag::class);` — без лишних указаний ключей), если таблицы названы правильно.

##### 1 Имя метода = имя связи:

Laravel выводит **имя внешнего ключа** из имени метода:

|Метод|Ожидаемая колонка FK|Ожидаемая таблица|
|---|---|---|
|`category()`|`category_id`|`categories`|
|`user()`|`user_id`|`users`|
|`author()`|`author_id`|`authors`|
|`postCategory()`|`post_category_id`|`post_categories`|

То есть метод `category()` в единственном числе → Laravel ищет `category_id` и таблицу `categories`. Всё это — **snake_case в единственном числе**.

##### 2 Как Eloquent угадывает таблицу:

Модель `Category` → таблица `categories` по правилу:

- класс → snake_case,
- единственное число → множественное.

```
Category   → categories
Post       → posts
UserProfile → user_profiles
```

Если таблица называется иначе (например, `cat_list`), нужно указать явно:

```php
protected $table = 'cat_list';
```


##### 3. Как угадывается внешний ключ

Для `belongsTo` — по имени метода: `category()` → `category_id`.

Для `hasMany` / `hasOne` — по имени **класса текущей модели**:

php

// В модели Category
public function posts()
{
    return $this->hasMany(Post::class); // ищет post_id в таблице posts
}

Здесь `posts()` → Laravel ищет `post_id` (единственное число от `Post`) в таблице `posts`.

#### 4. Если имена не совпадают с конвенцией

Всегда можно указать явно. У `belongsTo`:

```php
public function category()
{
    return $this->belongsTo(
        Category::class,   // связанная модель
        'cat_id',          // внешний ключ в таблице posts
        'id'               // ключ в таблице categories (обычно id, можно опустить)
    );
}
```



##### 5. Конвенция промежуточной таблицы (`belongsToMany`)

Для many-to-many Laravel ожидает таблицу с именем из **двух моделей в алфавитном порядке, единственном числе, snake_case**:

|Модели|Таблица|
|---|---|
|`Post` + `Tag`|`post_tag`|
|`User` + `Role`|`role_user`|
|`Category` + `Product`|`category_product`|

Порядок — **алфавитный**: `post_tag`, а не `tag_post` (post < tag).

Колонки в промежуточной таблице — `<модель>_id`:

```php
// Post.php
public function tags()
{
    return $this->belongsToMany(Tag::class); // таблица post_tag, колонки post_id, tag_id
}
```

Если таблица называется иначе — вторым аргументом:

```php
return $this->belongsToMany(Tag::class, 'post_tags');
```



## 7. Конвенции миграций

Чтобы конвенции Eloquent работали, миграции должны создавать правильные колонки:

```php

// create_posts_table
$table->foreignId('category_id')->nullable()->constrained('categories');
// или вручную
$table->unsignedBigInteger('category_id')->nullable();
$table->foreign('category_id')->references('id')->on('categories');

```

Для many-to-many:

```php
// create_post_tag_table
Schema::create('post_tag', function (Blueprint $table) {
    $table->foreignId('post_id')->constrained()->cascadeOnDelete();
    $table->foreignId('tag_id')->constrained()->cascadeOnDelete();
    $table->primary(['post_id', 'tag_id']); // составной PK
});
```
