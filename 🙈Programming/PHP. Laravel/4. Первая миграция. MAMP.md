### Создаем миграцию

```bash
# Можно создать миграцию
php artisan make:migration <name>

# Но лучше создать модель, которая создаст и миграцию (-m — создаст миграцию)
php artisan make:model Post -m
```

После `php artisan make:model` в `app/models` появилась модель `Post.php` и в `database/migrations` появилась миграция `2026_09_18_143257_create_posts_table`

#### create_posts_table.php:

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    /**
     * Run the migrations.
     */
    public function up(): void
    {
        Schema::create('posts', function (Blueprint $table) {
	        # laravel создал id и timestamps (created_at и updated_at)
            $table->id();
            $table->timestamps();

			# Добавляем новые поля:
			# string — ограничение 255 знаков
			$table->string('title');
			# text — без ограничений по знакам
            $table->text('content');
            # nullable — может быть NULL
            $table->string('image')->nullable();
            $table->unsignedInteger('likes')->nullable();
            # Стандартное значение (1)
            $table->boolean('is_published')->default(1);

        });
    }

    /**
     * Reverse the migrations.
     */
    public function down(): void
    {
        Schema::dropIfExists('posts');
    }
};
```

## Про миграции из deepseek

**Миграция** — это как **система контроля версий (Git), но только для структуры базы данных**.

Представь, что твоя БД — это дом. Ты его строишь: сначала фундамент (таблица `users`), потом стены (таблица `posts`), потом добавляешь комнату (новый столбец `avatar`). Миграция — это **пошаговая инструкция**, которая записывает каждое такое изменение, чтобы:

1. **Ты сам** не забыл, что и когда менял.
    
2. **Другие разработчики** в команде могли получить ту же структуру БД одной командой.
    
3. Можно было **откатить** изменения назад (rollback).
    

#### Как это работает в Laravel

Когда ты пишешь `php artisan migrate`, Laravel:

1. Смотрит в **специальную таблицу** `migrations` в БД — там хранится список уже применённых миграций.
    
2. Находит файлы миграций в папке `database/migrations/`, которые **ещё не применялись**.
    
3. Выполняет их по очереди (обычно по дате в имени файла, например `2024_01_15_000000_create_users_table.php`).
    
4. Записывает каждую применённую миграцию в таблицу `migrations`, чтобы в следующий раз её не выполнять повторно.
    

Пример файла миграции:
```php

public function up()
{
    Schema::create('users', function (Blueprint $table) {
        $table->id();
        $table->string('name');
        $table->string('email')->unique();
        $table->timestamps();
    });
}
public function down()
{
    Schema::dropIfExists('users');
}
```


- `up()` — что сделать при применении миграции (создать таблицу, добавить столбец и т.д.)
    
- `down()` — как откатить (удалить таблицу, убрать столбец)
    

#### Обновление БД — это миграция?

**Зависит от того, что ты имеешь в виду под «обновлением БД».**

|Что делаешь|Это миграция?|
|---|---|
|Меняешь **структуру** (добавил таблицу, столбец, индекс)|✅ **Да**, это миграция|
|Меняешь **данные** (обновил имя пользователя, удалил запись)|❌ **Нет**, это не миграция|
|Обновляешь **версию самого MySQL/PostgreSQL** на сервере|❌ **Нет**, это обновление СУБД|

То есть **миграция — это всегда про схему (структуру) БД**, а не про содержимое.

#### А как же обновление данных?

Для данных в Laravel есть отдельный инструмент — **сидеры** (`Seeders`) и **фабрики** (`Factories`). Они заполняют БД тестовыми или начальными данными, но не меняют структуру.

Если нужно изменить данные в рамках миграции (например, перенести значения из одного столбца в другой при рефакторинге) — это делают внутри `up()`, но это уже считается «миграцией данных» (data migration), и это более тонкий момент.

#### Итог

- **Миграция** = версионирование **структуры** БД.
    
- `php artisan migrate` = «применить все новые миграции, которых ещё нет в таблице `migrations`».
    
- **Обновление структуры** — да, миграция.
    
- **Обновление данных** — нет, это сидеры или ручные SQL-запросы.
    
- **Обновление версии СУБД** — нет, это администрирование сервера.
    

Главная польза миграций: **любой разработчик может развернуть точно такую же БД одной командой**, не копируя SQL-дампы вручную.
