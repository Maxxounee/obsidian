Большинство вещей, которые мы пишем в TS, не компилируются и не попадают в runtime. Enum — исключение. 
Вместо enum удобнее всего использовать const as const

```ts
/* Компилируется в объект в JS */  
enum UserRole {  
    USER = 'user',  
    ADMIN = 'admin'  
}  
  
/* Не компилируется в объект.  
  
Во всех местах, где в коде исользуется UserRole2.USER  
 просто подставляется строка со значением 'user' */
const enum UserRole2 {  
    USER = 'user',  
    ADMIN = 'admin'  
}  

// Оба enum'a можно дополнить
enum UserRole { TEST = '123' }  
const enum UserRole2 { TEST = 'asd' }  
  

// Обычный enum можно перебрать по ключам (потому что комплируется в объект)
for (const key in UserRole) {  
    console.log(key)  
}  

// Const enum нельзя перебрать. Будет ошибка (потому что компилируется в строку)
for (const key in UserRole2) {  
    console.log(key)  
}
```

Enum можно заменить обычным JS объектом

```ts
enum EUserRole {  
    USER = 'user',  
    ADMIN = 'admin',  
}  
  
const UserRole = {  
    USER: 'user',  
    ADMIN: 'admin',  
} as const; // делает все поля readonly при создании типа  
  
// 1. Тут тип некорректный. Мы получим поле type = { USER: 'user', ADMIN: 'admin' }  
type UserRole = typeof UserRole;  
  
// 2. Получим type = { USER: string, ADMIN: string }  
type UserRole = keyof typeof UserRole;  
  
// 3. Тут мы получим правильный type = { user: string, admin: string }  
type UserRole = typeof UserRole[keyof typeof UserRole];  
  
// 4. Но лучше использовать generic и вспомогательную функцию  
type ValueOf<T> = T[keyof T];  
type UserRole = ValueOf<typeof UserRole>;  
  
  
function fn(role: UserRole) {  
    console.log(role);  
}  
  
// Тут TS уже будет подсказывать из-за типа UserRole который мы создали  
fn('admin');  
// Можно использовать и так  
fn(UserRole.USER);  
// Можно и к простому enum  
fn(EUserRole.ADMIN);
```
