Преобразование типов подразумевает, что мы один тип явно или неявно преобразуем в другой.

```ts
let a = 10;
let b = a + '123'; // неявное преобразование
```

___

За счет структурной типизации, TS может приравнять объект obj к type Person из-за одинаковых полей. Мы сможем его так использовать.

Но если мы получим этот объект с backend в runtime, то ts ничего ему не назначит.
```ts
interface Person {  
    name: string;  
    age: number;  
}  

// Для TS это просто type === object
  
const obj = {  
    name: '123',  
    age: 13,  
}  

// Из-за хардкода TS и так подхватит поля name и age, но
// в реальном примере такого не будет. as Person решает проблему типизации
const j = JSON.parse(JSON.stringify(obj)) as Person;

// Варианты:

const obj = {  
    name: '123',  
    age: 13,  
} as Person;

// Это не дженерик! Аналог as Person.
const obj = <Person> {  
    name: '123',  
    age: 13,  
} 
```

#### satisfies

Ts проверит, соответствуют ли поля интерфейсу, но не назначит obj тип Person

```ts
const obj2 = {  
    name: '123',  
    age: 13,  
} satisfies Person;
```

## Когда допустимо использовать As

В продакшене лучше избегать его использования

Можно:

* В конфигах
* В тестах
* Иногда при работе с html элементами
* В утилитарных функциях (рассмотрим позже)
* Когда ТС не может вывести тип (рассмотрим позже)

### Пример хелпера

```ts
interface Person {  
    age: number;  
    name: string;  
}  
  
function JSONParse<T>(data: string): T {  
    return JSON.parse(data) as T;  
}  
  
const parsedJson = JSONParse<Person>('{ "age": 25, "name": "asd" }');
```

```ts
interface Person {  
    age: number;  
    name: string;  
}  
  
const obj: Person = {  
    age: 25,  
    name: 'str',  
}  

function keys<T extends object>(data: T): Array<keyof T> {  
    return Object.keys(data) as Array<keyof T>;  
}  
  
const res = keys(obj);
```
