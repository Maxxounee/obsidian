### Any

Можно сказать, что отключает любую проверку типов. Дословно — "любой тип". Лучше не использовать, убивает весь смысл TS. Any является и `надтипом`, и `подтипом` одновременно для всего (любому объекту/примитиву можно присвоить any, любой any переменной можно присвоить любые данные)

```ts
let value: any;
value = 5;
value = [];
value = 'str';
```


### Unknown

Unknown — "безопасный" аналог any. Используется тогда, когда мы не знаем, что за данные ожидать на вход (например, функции). TS требует проверки типа перед использованием. Unknown вынуждает делать ручные проверки и работать с данными правильно. 

Unknown является `superType` для всех других типов. Мы можем присвоить переменной с типом unknown любые данные. Любым данным мы не можем присвоить тип unknown.

```ts
function logData(data: unknown) {
	let value: string; // тут присвоить еще не можем
	
	if (typeof data === 'string') {
		value = data; // можем присвоить после проверки
	}
	if (Array.isArray(data)) {
		data.map(...)
	}
}
```

```ts
// unknown is superType

let value: unknown;

let str: string = value; // нельзя.
value = 42; // ок
value = 'str'; // ок
```

### Never. exhaustiveCheck

"Недостижимое" значение, то, что не может существовать — некий парадокс в типах. Зеркальная ситуация с unknown. Является subType (подтипом) для всех других типов.

Актуально для функций, в которых всегда происходит ошибка. Или для функций, в которых происходит бесконечный цикл

```ts
let value: never;
let str: string = value; // ok

let str: string = '123';
let value: never = str; // так уже нельзя
```

```ts
enum Values {
	FIRST,
	SECOND
}

function fn(value: Values) {
	switch(value) {
		case Values.FIRST:
			return 1;
		case Values.SECOND:
			return 2;
		default:
			return value; // Будет возвращать never. Потому что возможных значений всего два: FIRST и SECOND. До default никогда не дойдет
	}
}
```

Фишка с exhaustiveCheck. Мы можем завести переменную, которая будет типом never и принимать входящее значение функции. Если мы не обработаем все типы (все варианты аргумента), то TS выдаст ошибку для этой переменной (что она не может быть типом never).

```ts
enum Values {
	FIRST,
	SECOND,
	THIRD
}

function fn(value: Values) {
	switch(value) {
		case Values.FIRST:
			return 1;
		case Values.SECOND:
			return 2;
		default:
			const exhaustiveCheck: never = value; // тут TS будет ругаться, потому что появился третий value — THIRD, который мы не обработали. Соответственно exhaustiveCheck не может являться типом never.
			return value; 
	}
}
```

```ts
type RandomName = string & number; // такого пересечения быть не может. RandomName будет являться типом never.

const value: RandomName = 1; // Type 'number' is not assignable to type 'never'.
```

### Void

Тип, который означает, что функция ничего не возвращает

```ts
function fn(): void {
	console.log(123);
}
```
