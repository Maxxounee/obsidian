### Что такое http?

Http — hyper text transport protocol. Протокол общения между сервером и клиентом. Протокол подразумевает под собой метод (гет пост), адрес (url), заголовки (тип данных, хост, cors) и тело запроса.


### REST

REST — архитектурный стиль, который сообщает о том, как наиболее эффективно производить взаимодействие между сервером и клиентом (через API — программный интерфейс). Часто называют протоколом, но протоколом является HTTP, а rest — это именно архитектурный стиль (набор правил, чтобы сервер выдерживал нагрузки, легко читался, хорошо масштабировался и тд).

Концепции:

* Модель взаимодействия — клиент-сервер.
* Система может быть многоуровневой (для клиента это неважно. Для клиента точка входа одна, но на уровне сервера может быть распределение)
* Сервер не должен иметь состояние (не должен ничего хранить). При каждом запросе клиент и сервер общаются как в первый раз. Клиент должен отправлять все необходимые данные каждый раз (общение должно обладать полной информацией).
* Сервер должен иметь единый (унифицированный) интерфейс с единой семантикой (get post delete на своих местах. URL вида /products или /products/id)
* Идемпотентность (идентичность) — все запросы (даже повторяющиеся) должны иметь одинаковый эффект (кроме, естественно, post)
* Кеширование — должно быть реализовано кеширование (memcache, reddis). Актуально для get и post. Серверу не нужно вычислять запрос заново, если он уже был совершен и вычислен.
* Обмен данными — чаще всего JSON, но бывает и XML
* Обратная совместимость при версионировании `/posts/v2/` -> `posts/v3`. Сохранять старые api, если есть необходимость сильно менять поведение, и добавлять версию
