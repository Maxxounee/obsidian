## Что такое контракты и фасады в laravel

В Laravel **контракты** и **фасады** — это два разных, но взаимодополняющих инструмента для доступа к сервисам фреймворка. Контракты — это интерфейсы, которые определяют, _что_должен уметь делать сервис. Фасады — это «статичные» обёртки, которые дают удобный доступ к _реализациям_ этих сервисов.

### Контракты
**Контракты** — это набор интерфейсов, которые определяют основные сервисы Laravel. Проще говоря, это «договор» о том, какие методы должны быть у класса, но без конкретной реализации.

Например, контракт `Illuminate\Contracts\Queue\Queue` определяет методы, необходимые для постановки задач в очередь, а `Illuminate\Contracts\Mail\Mailer` — для отправки почты.

**Зачем они нужны:**

- **Явные зависимости:** Когда вы указываете интерфейс в конструкторе класса (через type-hint), вы сразу видите, какие сервисы нужны вашему классу. Это делает код более предсказуемым и облегчает его понимание.
    
- **Слабая связанность:** Ваш код зависит от абстракции (интерфейса), а не от конкретной реализации. Это значит, что вы можете легко заменить одну реализацию на другую (например, драйвер очереди или почтовый сервис) без изменения своего кода.
    
- **Идеально для пакетов:** Если вы пишете пакет, который должен работать с разными фреймворками, использование `illuminate/contracts` позволит вам избежать жесткой привязки к конкретной реализации Laravel.
    

**Как использовать:**  
Laravel автоматически разрешает (resolves) контракты через сервис-контейнер. Вам достаточно просто указать интерфейс в конструкторе класса, который разрешается контейнером (контроллеры, слушатели событий, middleware и т.д.):

```php
use Illuminate\Contracts\Cache\Repository as Cache;

class UserController extends Controller
{
    protected $cache;

    public function __construct(Cache $cache)
    {
        $this->cache = $cache; // Контейнер внедрит реализацию
    }
}
```
